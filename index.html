WeaveBench

A long-horizon, real-world benchmark of 114 tasks across 8 work domains where computer-use agents must interleave visual desktop control with command-line and code execution within a single trajectory. Rollouts run on a real Ubuntu desktop, audited by a trajectory-aware judge that detects fabricated screenshots, hard-coded metrics, and other shortcut behaviors.

Paper Teaser

Three workflows. Three reasons GUI-only or CLI-only is not enough.

A data-analyst / SRE chasing a slow Jaeger span, a game-dev fixing off-screen labels and missing sprites, and a web ops engineer reproducing a 15:42 503 spike. Every task interleaves GUI inspection with CLI/code verification — that interleaving is what WeaveBench measures.

Figure 1 from the paper. Each scenario lists why a CLI-only or GUI-only agent would fail. WeaveBench encodes the full interleaving as a single trajectory.

01 / Core Idea

Evaluate cross-interface orchestration, not isolated capabilities.

Deployed CUA runtimes already integrate GUI control, CLI/code execution, browsers, and external tools inside one agent loop. Existing benchmarks test these channels in isolation, leaving the orchestration layer under-measured. WeaveBench is built around tasks where success requires the agent to weave both channels together.

GUI and CLI are complementary, not interchangeable.

GUIs expose rendered, transient, spatial state — canvases, dialogs, visual feedback. CLI/code expose structured, scriptable, persistent state — source files, configs, logs, services. Real workflows braid them: observe in the GUI, verify in the shell, edit in code, re-render, re-observe.

03 / Method

A hybrid harness, a trajectory-aware judge, and shortcut auditing.

WeaveBench evaluates four deployed harnesses on the same Ubuntu desktop with the same GUI plugin (one screenshot primitive + nine pyautogui actuation primitives). A trajectory-aware Agent-as-a-Judge then scores eight quality dimensions while a shortcut scanner zeroes confirmed hacks.

M1

Hybrid Harness

A unified Ubuntu desktop wraps four production-grade computer-use stacks: OpenClaw (our reference harness; OpenAI Responses / Anthropic Messages / OpenAI Chat transports), Codex CLI, Claude Code, and Hermes. All four share the same GUI plugin so differences reflect orchestration, not tooling.

M2

Trajectory-Aware Judge

For every task, an LLM judge inspects the full transcript and any deliverables, then rates 8 dimensions: task completion, deliverable correctness, deliverable quality, evidence authenticity, tool-use correctness, final-state correctness, efficiency / robustness, and instruction following.

M3

Anti-Shortcut Scan

A separate scanner runs nine pattern detectors over the trajectory: synthetic-screenshot rendering, hard-coded metrics, mock services, duplicate crops, overlay manipulation, ground-truth leakage, runtime injection, regenerated fixtures, and fabricated screenshots. Any hit forces the task score to zero.

M4

Layered Scoring

The reported PassRate uses a layered min: a task contributes a non-zero score only if no shortcut was confirmed and the deliverable itself passes a domain-specific check. This is what keeps a 53.5% (outcome-only) headline from masking a 33.3% (trajectory-aware) reality.

04 / Main Results

Frontier models stall at 41.2% PassRate — with substantial harness sensitivity.

05 / Ablations

Two ablations that change how you read the leaderboard.

The first explains why GUI-only or CLI-only setups under-perform a hybrid one. The second shows what happens when you grade only on final outcomes vs. on full trajectories.

Interface mode

GUI-only and CLI-only both fall short of Hybrid.

We rerun the strongest model under three interface restrictions: GUI-only (no shell/code), CLI-only (no screen capture / pointer), and Hybrid (the default). The PassRate gap is consistent with the design claim — the two channels carry complementary state.

Judge ablation

Trajectory-aware grading removes 10–20 PR points of false credit.

A final-state-only judge accepts shortcut behaviors (synthetic screenshots, hard-coded metrics) that a trajectory-aware judge rejects. The headline-vs-reality gap is largest on the strongest models, precisely those most rewarded by shortcut reward hacking.

06 / Failure Analysis

What actually goes wrong in 1,735 failed trials.

Across 2,209 graded trials, 1,735 were failures. We hand-coded a five-category, fifteen-subclass failure taxonomy and re-attributed every failed run. The big finding: tool-use posture — not raw reasoning — dominates, and the GUI↔CLI handoff is where most posture mistakes happen.
